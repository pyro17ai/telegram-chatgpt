# Реактивация клиентов Каре Мебель

Применяй эти правила, когда пользователь поручил работу с прежними покупателями. Они дополняют скилл Telegram и не заменяют проверку проекта в KCRM. Значение статуса "заказной КП" пока не подтверждено как признак оплаты; не делай такой вывод по названию.

## Точное сопоставление

Сначала нормализуй телефон из CRM в международный формат и зафиксируй, откуда он получен. Удалять пробелы и скобки допустимо; подставлять страну без основания или сравнивать только последние цифры нельзя. Ищи полное совпадение с `phoneNumber` в свежем результате `getContacts()`. Для Telegram номер может возвращаться без знака `+`.

У подходящего адресата должны совпасть полный номер и существующий контакт Ивана. Затем проверь доступную личную историю с этим пользователем. Пустой диалог или только служебное событие не подтверждают прошлую переписку. Полученный через поиск peer сам по себе не доказывает выполнение этих условий. Если совпадение неоднозначно или телефон скрыт, сохрани причину пропуска; имя и username не заменяют проверку номера. Не импортируй новые контакты ради прохождения этого фильтра.

Несколько оплаченных проектов одного контакта объединяй по проверенному Telegram user ID. Историю покупок учитывай совместно, чтобы человек не получил отдельное сообщение за каждый проект. Для анализа читай доступную переписку в согласованном объёме и сохраняй ссылки на факты, из которых получился текст.

## Черновики и отправка

До запуска партии определи каталог результата в проекте. В Markdown сохраняй адресата и связь с CRM, затем предлагаемый текст. Для пропущенного контакта укажи конкретную причину: нет телефона, нет точного совпадения, нет прежней переписки или результат требует уточнения. Недоступность Telegram передавай следующему этапу проекта; этот скилл не отправляет сообщения через другие каналы.

В запросе на подготовку результата остановись на локальных черновиках. Отправляй только ту партию, которую пользователь поручил отправить. В самом сообщении опирайся на подтверждённые покупки и переписку; не придумывай обстоятельства знакомства.

## Повторный запуск

Для партии сохраняй журнал в каталоге профиля, например `outreach.jsonl`, с идентификатором кампании и Telegram user ID. До отправки запиши состояние `pending` вместе с хешем текста. После ответа Telegram сохрани `messageId` и состояние `sent`; неизвестный результат помечай `uncertain`. Это работа кода конкретной партии: общий модуль подключения журнал не ведёт.

Повторно не отправляй тому же пользователю в той же кампании после `sent`, даже если текст поменялся. При `pending` или `uncertain` сначала проверь историю и восстанови результат. Если остаётся неоднозначность, сохрани её для ручной проверки. Локальный журнал сам по себе не гарантирует однократную отправку при сетевом сбое.
