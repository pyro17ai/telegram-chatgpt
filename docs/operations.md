# Эксплуатация

Сервер хранит индекс SQLite и зашифрованные объекты в Docker volume `telegram_data`. Ключ шифрования и ключ владельца находятся в `.env`. Для резервной копии нужны и volume, и исходный ключ шифрования. Храните их в приватном зашифрованном резервном хранилище; копия одного volume без ключа не восстановит сессию.

Перед обновлением сделайте резервную копию. Затем выполните `git pull` и `docker compose up -d --build`. Не запускайте configure повторно и не меняйте `TG_STATE_KEY`: новый ключ не сможет расшифровать прежние данные. Сборка применяет только новые миграции при старте сервера. Применённые миграции нельзя переписывать.

Для смены ключа владельца замените `SETUP_TOKEN` новым случайным 32-байтовым значением в hex и перезапустите сервис. Существующие браузерные сессии живут до 12 часов. Для немедленного отзыва всех браузерных/OAuth-сессий остановите приложение и выполните удаление строк таблицы `auth` через SQLite; данные Telegram при этом остаются. Для отзыва Telegram-сессии используйте Telegram → Настройки → Устройства. После отзыва потребуется заново настроить экземпляр; автоматическое удаление аккаунта через MCP не предусмотрено.

На Sites сохраняйте текущий ключ в runtime secrets и приватность сайта. D1 содержит небольшие индексы, R2 содержит зашифрованные объекты. Следите за квотами хранилища: R2 снимает предел одной строки D1, но не отменяет ограничения аккаунта и памяти Worker. Результаты запусков сохраняются для безопасного повтора request_id; автоматическое удаление истории запусков не включено.

Успешный `/health` подтверждает работу HTTP-процесса. `runtime_diagnostics` подтверждает наличие сохранённого аккаунта. Только успешный `getMe` подтверждает действующую Telegram-сессию.
