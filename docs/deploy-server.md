# Сервер без покупки домена

Владелец передаёт агенту ссылку на репозиторий и SSH-доступ. Агент разворачивает сервис и возвращает персональную ссылку. Владелец проходит вход в Telegram на странице и добавляет скачанный пакет в ChatGPT. Регистрировать домен или аккаунт для туннеля не требуется.

## Что делает агент

1. Подключись к указанному серверу и проверь ОС. Нужен публичный IPv4 с входящими TCP 80/443. Если используются NAT или облачный firewall, настрой доступ к этим портам. Проверь, не заняты ли они существующим сервисом. Установи Git и [Docker Engine с Compose](https://docs.docker.com/engine/install/) официальным способом для этой ОС. Не отключай firewall целиком и не останавливай чужие сайты. На сервере только с IPv6 используй Sites либо адрес, который уже обслуживает его reverse proxy; автоматический режим этой версии рассчитан на IPv4.

2. Склонируй репозиторий в отдельный каталог и запусти `bash scripts/deploy.sh`. Скрипт использует Node.js внутри Docker, определяет внешний IPv4 через HTTPS и проверяет DNS бесплатного имени. Если публичный адрес известен из SSH-подключения или панели сервера, можно явно передать `--ip ПУБЛИЧНЫЙ_IP`, особенно при NAT или исходящем прокси. Установщик создаёт приватный `.env`, запускает приложение с Caddy и ждёт готовности HTTPS. Он сохраняет имеющийся `.env` при повторном запуске; сгенерированные ключи не меняются.

3. После успешного запуска повтори проверку `/health` и `/.well-known/oauth-authorization-server` из своей внешней среды с обычной проверкой сертификата. `/mcp` без токена должен отвечать 401. Затем передай владельцу персональную ссылку из вывода и объясни следующий шаг: пройти Telegram-вход, скачать `Telegram.zip`, передать его Plugin Creator в веб-версии ChatGPT и подтвердить OAuth. Обычный адрес и `/mcp` публичны, персональная ссылка содержит секрет владельца. Не публикуй её.

## Адрес и HTTPS

Для IPv4 сервер получает имя `telegram.<IP-через-дефисы>.sslip.io`. DNS-записи создавать не нужно. Имя вычисляется из IP и сохраняется в `.env`, поэтому перезапуск контейнера или повторная установка поверх существующей конфигурации не меняет OAuth issuer и адрес MCP. Caddy сохраняет сертификаты в volume и автоматически продлевает их.

Это бесплатный адрес стороннего DNS-сервиса. Он работает, пока доступны DNS-сервис и ваш публичный IP. [Документация sslip.io/nip.io](https://nip.io/) подтверждает поддержку HTTPS через обычный HTTP-01 challenge, а также описывает общие лимиты центров сертификации. [Caddy](https://caddyserver.com/docs/automatic-https) получает и продлевает сертификаты автоматически. Выдача сертификата требует доступности сервера из интернета; локальная успешная сборка этого не подтверждает.

Если sslip.io недоступен, при **первой** установке можно выбрать `bash scripts/deploy.sh --dns-suffix nip.io`. Не переключай рабочую установку на новое имя автоматически: ChatGPT хранит предыдущий URL и OAuth issuer.

Свой домен по желанию: `bash scripts/deploy.sh --domain telegram.example.com`. Его DNS должен указывать на сервер. Этот режим не нужен для обычной установки.

## Если установка остановилась

При недоступном Docker исправь запуск демона или права текущего пользователя. Если не удалось определить IP, передай `--ip`. Закрытые 80/443, неправильный IP или лимит выпуска сертификатов видны в `docker compose logs --tail=80 caddy`. Исправь причину и повтори `bash scripts/deploy.sh` без параметров. Не удаляй `.env` и volumes; не используй `curl -k` как подтверждение готовности.

Если `.env` уже создан, смена адреса требует изменить **только** `PUBLIC_ORIGIN` и `DOMAIN`, сохранив ключи. Примени конфигурацию через `bash scripts/deploy.sh`. При смене имени перезапусти Caddy командой `docker compose restart caddy`: приложение Caddy читает адрес при старте. Затем скачай новый ZIP и переподключи плагин в ChatGPT. После изменения IP сервера сделай то же самое с новым бесплатным именем.

Если 80/443 заняты существующим reverse proxy, сохрани его. Настрой HTTPS для сгенерированного имени в этом proxy, направь запросы на приложение по закрытой сети Docker и запускай только сервис `telegram` через `docker compose up -d --build telegram`. Входящие identity-заголовки приложение отбрасывает. Подробнее о данных и резервных копиях: [operations.md](operations.md).
